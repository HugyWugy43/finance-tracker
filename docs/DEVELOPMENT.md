# Разработка ORBIT

## Как проходит операция

`components/finance-app.tsx` управляет состоянием приложения. Форма в `components/forms.tsx` собирает данные, `lib/api.ts` отправляет запрос в `app/api/transactions/route.ts`. Серверные функции из `lib/server.ts` проверяют запрос и владельца записи, затем сохраняют данные в D1. После успешного ответа интерфейс обновляет список и расчёты.

Экраны вынесены в отдельные компоненты: авторизация — `auth-screen.tsx`, обзор — `overview.tsx`, профиль — `profile-view.tsx`, список операций — `transaction-list.tsx`, графики — `charts.tsx`. Общие вычисления находятся в `lib/finance.ts`, диапазоны дат — в `lib/expense-period.ts`, геометрия диаграммы — в `lib/chart-geometry.ts`.

## Правила данных

- Деньги хранятся целым числом копеек. Не сохраняйте дробные рубли вместо копеек.
- Даты операций — календарные даты `YYYY-MM-DD`. Учитывайте местную дату, чтобы UTC-преобразование не сдвигало день.
- Неделя включает выбранную дату и следующие шесть дней.
- Общий баланс и расходы выбранного месяца имеют разные диапазоны расчёта.
- Проверки TypeScript не заменяют серверную валидацию и проверку принадлежности записи пользователю.
- Деморежим нужен для знакомства с интерфейсом; личные записи сохраняются в базе.

## Как проверять изменения

После редактирования выполните `npm run format`, `npm run typecheck` и `npm run lint`. Форматтер пропускает зависимости, сгенерированные файлы, базу и результаты тестов. Для автоматической проверки оформления есть `npm run format:check`.

Браузерным тестам нужен запущенный сервер и установленный Chrome. По умолчанию используется порт 5173; переменная `ORBIT_URL` меняет адрес.

| Файл                          | Назначение                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------------- |
| `tests/verify.mjs`            | API, авторизация и основные пользовательские действия; создаёт тестовые аккаунты в локальной базе |
| `tests/usability.mjs`         | Удобство интерфейса, переключения, диапазоны и адаптация                                          |
| `tests/chart-readability.mjs` | Читаемость диаграмм                                                                               |
| `tests/visual.mjs`            | Проверки отображения и снимки экранов                                                             |
| `tests/project-health.mjs`    | Адаптивная вёрстка и ошибки страницы                                                              |

Интерфейсные проверки с подставленными ответами API не заменяют тесты настоящего сервера. Результаты и скриншоты лежат в `test-results/`. `npm test` останавливается на первом упавшем сценарии.

Проверяйте изменения вёрстки на узком телефоне и настольном экране, а также с отключёнными анимациями. В `app/styles.css` есть адаптивные переопределения: прежде чем добавлять новое правило, найдите существующие селекторы и условия media query.

## Сборка и база

`npm run build` создаёт клиентскую и серверную части. `npm start` запускает собранную версию на порту 4173; приложение нельзя запустить двойным щелчком по HTML. При ошибке доступа к файлам сборки в Windows сначала остановите работающий preview через Ctrl+C.

`wrangler.jsonc` связывает приложение с локальной D1. Техническое имя базы оставлено для совместимости с существующим хранилищем. Перед изменением схемы сохраните резервную копию `.wrangler/state` при остановленном сервере. Копия содержит персональные данные и не должна попадать в репозиторий.

Несколько script-тегов в HTML создаёт Vinext для загрузки React и восстановления интерфейса после серверного рендеринга. Редактировать их в `dist/` вручную не нужно: исправления делаются в исходниках и пересобираются.
