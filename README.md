# ORBIT — личные финансы

Курсовой проект с упором на frontend: React 19, TypeScript, HTML и обычный CSS. Только тёмная тема. Пользователь вручную добавляет доходы и расходы; данные сохраняются в SQLite через локальную Cloudflare D1.

## Запуск

Нужен Node.js 22.13 или новее и npm.

```powershell
npm ci
npm run dev
```

Приложение: http://127.0.0.1:5173/. Демо: http://127.0.0.1:5173/?demo=1.

Для **новой пустой базы** перед первым запуском выполните `npm run db:migrate`. Существующая база находится в `.wrangler/state`; повторно применять исходную миграцию к ранее созданным вручную таблицам не нужно. При очистке проекта база и её идентификатор сохранены. Поэтому техническое имя базы `site-creator-d1` оставлено в `wrangler.jsonc`.

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm start
```

`npm start` открывает собранную версию на http://127.0.0.1:4173/. Проверки требуют запущенного сервера и Chrome. По умолчанию они используют порт 5173; другой адрес задаётся через `ORBIT_URL`. Тесты API создают отдельные тестовые аккаунты. Скриншоты и отчёты сохраняются в `test-results/` и исключены из Git.

## Структура

```text
app/
  page.tsx, layout.tsx     HTML-оболочка и точка входа
  styles.css              стили, адаптация и анимации
  api/                    регистрация, сессии, операции, бюджет, профиль
components/               React-компоненты экранов, форм, диаграмм и бренда
lib/                      типы, расчёты, валидация, API-клиент и серверные функции
db/schema.ts              схема для генерации миграций
drizzle/                  SQL-миграции и их метаданные
public/                   используемые изображения и локальные шрифты с лицензиями
scripts/runtime-env.mjs   локальные настройки среды запуска
tests/                    функциональные и браузерные проверки
vite.config.ts            сборка React и серверных маршрутов
wrangler.jsonc, worker.ts подключение локальной D1 и обработчик запросов
```

`node_modules/`, `dist/`, `.vinext/`, `.next/`, `.wrangler/` и `test-results/` — зависимости, результаты сборки или локальные данные, а не исходники. `.wrangler/state` содержит аккаунты и операции: её удаление сбросит данные.

## Возможности

- Регистрация: имя, почта, пароль, подтверждение и индикатор надёжности. Технический никнейм создаётся сервером автоматически.
- Вход, личный кабинет, изменение профиля, выход и сохранение сессии.
- Добавление, изменение и удаление расходов и доходов.
- Обзор, месячный бюджет с непрерывной полосой, категории, поиск, фильтры и CSV.
- Расходы за день, неделю или месяц. Неделя начинается с выбранной даты и длится семь дней; переход в историю сохраняет диапазон.
- Выбор дня на графике мышью, касанием или ползунком с клавиатуры.
- Адаптивность, локальные шрифты Onest и Golos Text, отключение анимации через `prefers-reduced-motion`.

Пароли хешируются с солью, сессии используют HttpOnly-cookie. Сервер проверяет принадлежность операций аккаунту; суммы хранятся целым числом копеек. Банковской интеграции нет; подтверждение почты и восстановление пароля не реализованы.

## Почему в HTML несколько script-тегов

Исходный HTML задаётся в `app/layout.tsx`; отдельного `index.html` здесь нет. Vinext собирает React и серверные маршруты через Vite. В режиме разработки он добавляет модули для быстрой перезагрузки. В production остаются файлы React, загрузчика и приложения, а также небольшие inline-блоки с данными серверного рендеринга для запуска React в браузере. Это служебный код фреймворка, а не отдельные сторонние виджеты. Удалять его вручную из `dist/` нельзя — перестанет работать интерфейс, а следующая сборка создаст его снова.

Встроенный внешний скрипт Figma capture удалён. `chatgpt-auth.ts` был неиспользуемой заготовкой входа через ChatGPT из стартового шаблона; он не обеспечивал подключение помощника и не участвовал в авторизации ORBIT. Он удалён вместе с коннекторами и вспомогательным Sites-кодом. Локальное приложение запускается независимо от них.

Для разработки оставлены необходимые инструменты сборки, TypeScript, ESLint, Prettier и Playwright. Неиспользуемые shadcn-компоненты, Tailwind, библиотеки виджетов, примеры, старые CSS-файлы и шрифт Manrope удалены. `next` остаётся для совместимых типов и конфигурации фреймворка.

## С чего начать пользователю

Для знакомства откройте демо без регистрации. Для своих записей создайте аккаунт: он начнётся с пустой истории. В «Обзоре» видны баланс и бюджет, в «Операциях» можно искать и редактировать записи, в «Аналитике» — изучать расходы, в «Профиле» — менять сведения об аккаунте. Суммы вводятся вручную: приложение не получает данные из банка.

## Для разработчика

[Устройство приложения и проверки](docs/DEVELOPMENT.md) описывает поток данных и правила изменений. Для единообразного оформления исходников используйте `npm run format`, для проверки оформления — `npm run format:check`.

Чтобы увидеть результаты отдельных проверок интерфейса, запустите сервер и выполните во втором терминале:

```powershell
npm run test:usability
```

Для собранной версии на порту 4173 сначала задайте `$env:ORBIT_URL = 'http://127.0.0.1:4173'`. Тест выводит названия проверок и статусы PASS/FAIL; при ошибке выполнение останавливается. `npm test` последовательно запускает весь набор тестов. API-тесты создают локальные тестовые аккаунты со случайными паролями.

## Что можно передавать и удалять

Перед публикацией прочитайте [памятку о конфиденциальных данных](docs/PRIVACY.md). Не включайте в архив `.wrangler/`, `.env*`, `.dev.vars*`, результаты тестов и выгрузки с личными операциями. `.gitignore` не защищает обычный ZIP-архив.

При остановленном приложении можно удалить `node_modules/` (восстановить через `npm ci`), `dist/` (через `npm run build`), `.next/`, `.vinext/`, `.npm-cache/` и `test-results/`. Сохраняйте `package-lock.json`: он фиксирует версии зависимостей. **Не удаляйте `.wrangler/state`, если нужны аккаунты и операции.**
